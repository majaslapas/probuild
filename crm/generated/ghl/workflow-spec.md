# Workflow spec — „Mājaslapa → Pieteikumi“

Generated by scaffold.py (full level). Build in GHL → Automation → Workflows. Clicks and UI gotchas: the skill's references/ghl-ui.md.
`D(key)` = `{{inboundWebhookRequest.payload.data.key}}` · `P(x)` = `{{inboundWebhookRequest.payload.x}}` — type them, or pick them with the tag icon (Inbound Webhook Trigger › Payload › Data › Key).

## 0. Create first

- Custom fields from `ghl/custom-fields.csv` (folder „Mājaslapas pieteikums“; open each after saving and check its key is ASCII).
- Pipelines: „Mājaslapas pieteikumi“ (first stage „Jauns pieteikums“).
- Tags: `majaslapa`, `forma-<form key>` (created by the dynamic tag).

## 1. Trigger

- Add new trigger → **Inbound Webhook**. Copy the URL (copy icon) → password manager + `save-hook-url.sh`. Never paste it into chat, files or commands.
- Post `samples/mapping-sample.json` with `ghl-probe.sh`, then **Mapping reference** → that request → Save trigger.

## 2. Actions, in this order

1. **If / else „Valid“**
   - Branch „Webflow site“: Inbound webhook trigger › payload › siteId **is** `6adf4142414584038f9dbb34`
   - None branch: leave empty (ends). Inserted above existing actions, GHL moves them into the first branch.
   - After the production domain is live (optional): add `payload › data › site_host` condition so staging tests stop.
2. **Create contact**
   - First Name ← `{{inboundWebhookRequest.payload.data.vards}}`
   - Email ← `{{inboundWebhookRequest.payload.data.epasts}}`
   - Phone ← `{{inboundWebhookRequest.payload.data.phone_e164}}`
   - Contact Source ← `{{inboundWebhookRequest.payload.data.channel}}` (the latest sign-up's channel; each opportunity keeps its own)
   - An existing contact (duplicate rule of the sub-account) is updated; empty values do not wipe stored ones.
3. **Add contact tag**
   - `majaslapa`
4. **Add contact tag (dynamic)**
   - `forma-{{inboundWebhookRequest.payload.data.form_key}}` — a bare `forma-` tag later means the site script didn't run
5. **Create opportunity**
   - Pipeline „Mājaslapas pieteikumi“, stage „Jauns pieteikums“, status Open, value empty
   - Duplicate opportunities → **Enable duplicates for this action** (one opportunity per sign-up)
   - Opportunity Name ← `{{inboundWebhookRequest.payload.data.subject}} — {{inboundWebhookRequest.payload.data.vards}}`
   - Opportunity Source ← `{{inboundWebhookRequest.payload.data.purpose}}`
   - Forma ← `{{inboundWebhookRequest.payload.data.form_key}}` (also the dynamic form tag)
   - Mērķis ← `{{inboundWebhookRequest.payload.data.purpose}}` (same as Opportunity Source; a field filters more easily)
   - Lapa ← `{{inboundWebhookRequest.payload.data.page_path}}`
   - Objekta adrese vai pilsēta ← `{{inboundWebhookRequest.payload.data.vieta}}`
   - Ziņa ← `{{inboundWebhookRequest.payload.data.zina}}`
   - Kalkulatora aprēķins ← `{{inboundWebhookRequest.payload.data.aprekins}}`
   - Aprēķina jomas ← `{{inboundWebhookRequest.payload.data.aprekins_joma}}`
   - Aprēķina darbu skaits ← `{{inboundWebhookRequest.payload.data.aprekins_darbi}}` (in the action: ⋮ → Dynamic, then pick the value)
   - Aprēķina summa (€) ← `{{inboundWebhookRequest.payload.data.aprekins_summa}}` (in the action: ⋮ → Dynamic, then pick the value)
   - Aprēķins no (€) ← `{{inboundWebhookRequest.payload.data.aprekins_no}}` (in the action: ⋮ → Dynamic, then pick the value)
   - Aprēķins līdz (€) ← `{{inboundWebhookRequest.payload.data.aprekins_lidz}}` (in the action: ⋮ → Dynamic, then pick the value)
   - Ikmēneša maksa (€) ← `{{inboundWebhookRequest.payload.data.aprekins_menesi}}` (in the action: ⋮ → Dynamic, then pick the value)
   - Pakalpojums ← `{{inboundWebhookRequest.payload.data.pakalpojums}}`
   - Interese ← `{{inboundWebhookRequest.payload.data.interese}}`
   - Nomas sākums ← `{{inboundWebhookRequest.payload.data.no}}`
   - Nomas beigas ← `{{inboundWebhookRequest.payload.data.lidz}}`
   - Vēlamais datums ← `{{inboundWebhookRequest.payload.data.datums}}`
   - Nomas ilgums ← `{{inboundWebhookRequest.payload.data.ilgums}}`
   - Tehnika ← `{{inboundWebhookRequest.payload.data.produkts}}`
   - Projekts ← `{{inboundWebhookRequest.payload.data.projekts}}`
   - Avots ← `{{inboundWebhookRequest.payload.data.channel}}` (utm_source / google-ads / meta-ads / referring site / unknown)

   - UTM medium ← `{{inboundWebhookRequest.payload.data.utm_medium}}`
   - UTM campaign ← `{{inboundWebhookRequest.payload.data.utm_campaign}}`

6. **Add to notes**
   - Title: `Mājaslapas pieteikums: {{inboundWebhookRequest.payload.data.subject}}`
   - Body: `ghl/note.txt` (type label and placeholder separately when automating the editor)
7. **Send internal notification**
   - Type Email · To: Custom email: probuildlatvia@gmail.com
   - Subject: `Jauns pieteikums: {{inboundWebhookRequest.payload.data.subject}} — {{inboundWebhookRequest.payload.data.vards}} ({{inboundWebhookRequest.payload.data.site_host}})`
   - Message: editor **</>** source view → paste `ghl/email.html`
   - From name + From email only together, on a verified sending domain; else leave both empty
   - GHL appends an Unsubscribe link — nobody should click it

## 3. Workflow settings

- Allow re-entry ✓ · Allow multiple opportunities ✓ · Stop on response ✗ · no time window
- Publish (Draft → Publish) before the Webflow webhook is connected, then probe — only probes can trigger it then.

- `ghl-probe.sh` each `samples/probe-*.json`, then the mapping sample again (must stop at „Valid“).
- Execution logs: every action Executed; contact, opportunity fields (date not shifted), tags, note, e-mail.
